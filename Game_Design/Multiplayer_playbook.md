# Multiplayer playbook (YgoDuelist)

How co-op stays in lockstep with vanilla checksums, what usually desyncs, and how to hunt it without reading the whole repo line-by-line.

## Ground rules

- **Authoritative simulation:** Host and client must execute the **same** `GameAction` queue outcomes. UI-only differences are fine; **HP, block, powers, piles, pets, and RNG consumption** are not.
- **You do not own the entire stack:** `CreatureCmd`, `Hook.IterateHookListeners`, pile internals, and much of `sts2.dll` define order too. The mod fixes **what we control**: our collections, our `FirstOrDefault` picks, our patches next to play/checksum paths, and our deferred work.
- **Evidence is one input, not the only strategy:** When a desync lands, logs are gold. Between incidents, use **mechanical greps** (forbidden patterns) and a **small MP matrix** so you are not waiting for rare combinatorial explosions in prod.

## Where desyncs actually come from (high signal)

| Class | Why it splits host/client |
|-------|---------------------------|
| **Unstable iteration** | `PlayerCombatState.Pets` is a `List` exposed as `IReadOnlyList`; `foreach` throws if mutated mid-loop; `FirstOrDefault` without a stable sort picks different pets when list order differs. |
| **Unstable pools before RNG** | Same seed + `UnstableShuffle` still diverges if the **input sequence** to shuffle differs (e.g. card pool enumeration order). |
| **“First” in a zone** | `zone.Cards.FirstOrDefault(...)` when multiple cards qualify — pile order may not match across peers. |
| **Powered self-damage + Die For You** | `ValueProp.Move` without `Unpowered` is a **powered attack**; `DieForYouPower` redirects via `Hook.ModifyUnblockedDamageTarget` listener order (ally/pet ordering). |
| **Deferred combat work** | `SceneTreeTimer` / tweens completing **after** a checksum point while state already advanced on the other peer (pet death tails, UI relocation). |
| **Remote mirror assumptions** | `NetPlayCardAction` paths that assume `owner` or `CombatState` is non-null; option-pile plays that skip parity with host spend/stance. |

## Forbidden patterns (red)

Treat these as **guilty until proven innocent** in any code path that runs during combat on either peer:

- `PlayerCombatState.Pets.FirstOrDefault(...)` **without** a deterministic order (prefer shared helper below).
- `PlayerCombatState.Pets.Any(...)` on the **live** list during combat (collection-modified risk; no explicit `CombatId` scan order) — use **`YgoMpCombatOrder.PetsAny`**.
- `foreach (Creature pet in player.PlayerCombatState.Pets)` when **anything** in the body can add/remove pets or call into registry/commands that do — use **`.ToList()`** or iterate a sorted snapshot.
- `Dictionary` / `HashSet` enumeration driving **gameplay** (not just logging) when order must match vanilla serialization expectations.
- `zone.Cards.FirstOrDefault` / `First()` for **“pick one”** when ties are possible — sort by stable key (e.g. `CardId.Entry`) then take first.
- Raw `CardSelectCmd.FromSimpleGrid(...)` for **combat-path preview/confirmation-only grids** (`MinSelect = MaxSelect = 0`, manual confirm) — route through a synced helper so stale buffered `Index` choices cannot satisfy a later preview prompt.
- Raw `CardSelectCmd.FromSimpleGrid(...)` for **combat-path singleton activation prompts** or **deck / graveyard / hand candidate grids** that are ordinary `CardModel` lists — route through synced grid helpers with a stable candidate rebuild (`YgoMpCombatOrder.CardsSnapshotOrderedForMp(...)` + combat wire) instead of vanilla index resolution.
- Re-introducing per-card graveyard patch dispatch (e.g. `CardPileAddInternal*` calling `YgoSomeNamedCardGraveyard` directly) after `IYgoOnAddedToYgoGraveyardPile` already exists — that splits one timing across many bespoke code paths and is harder to audit for parity.
- Repeating ad-hoc `new BlockingPlayerChoiceContext()` creation in every file for the same activation/search/cleanup flow — centralize on `YgoChoiceContexts.Blocking(...)` so choice-context semantics stay searchable and consistent.
- Repeating raw `PileType.*.GetPile(player)` / custom-pile `.GetPile(player)` lookups throughout gameplay code when a shared accessor exists — centralize on `YgoPlayerPiles` so pile ownership resolution stays searchable and consistent across cards/services/patches.
- Repeating raw `PlayerRunTrunk` / `PlayerRunSideDeck` / `PlayerRunExtraDeck` ownership checks and `GetOrCreatePile` calls throughout run-state code when a shared accessor exists — centralize on `YgoPlayerRunPiles` so non-combat deck/trunk/extra-deck flows do not drift into subtly different ownership/null contracts.
- Repeating raw graveyard pile ownership / membership reads (`GraveyardPile.CustomType.GetPile(...)`, `GraveyardRelic.GetGraveyardCards(...)`, `Contains(...)`) throughout ordinary gameplay code when a shared accessor exists — centralize on `YgoPlayerPiles.Graveyard*` so graveyard-state reads stay grep-friendly and consistent.
- Repeating raw extra-deck / banished / monster-zone / option-pile ownership reads when `YgoPlayerPiles` already exposes the pile — centralize there so commands, net helpers, and ordinary card logic do not drift into different null/ownership contracts.
- Repeating `DuelMonsterFieldRegistry.GetFieldMonsters(...).ToList()`, raw `foreach`, or direct `Contains(...)` in gameplay code when the shared ordered/contains helpers exist — centralize on the registry helper so field-monster scans stay deterministic and grep-friendly.
- Repeating direct `DuelMonsterFieldRegistry.GetSourceCardForPet(...) == ...`, `ReferenceEquals(...)`, or local cast chains when `HasSourceCard(...)` / `GetSourceMonster<T>(...)` already express the binding check — centralize on the registry helper so pet-source resolution stays deterministic and grep-friendly.
- **Life costs** modeled as `CreatureCmd.Damage(..., player.Creature, ..., ValueProp.Move)` only — if it must **not** interact with Die For You / thorns-style “powered hit” rules, use **`Move | Unpowered`** (see Needle Ball self-burn).
- **Fire-and-forget `async void`** on `Hook.*` postfixes that mutate combat state — completion order vs checksum is fragile; prefer awaited chains or explicit deferral that matches host/client.

## Shared conventions and helpers (green)

**Prefer one obvious way to iterate pets for logic:**

- **`YgoMpCombatOrder`** (`YgoDuelistCode/Services/YgoMpCombatOrder.cs`) — use instead of ad-hoc `Pets.FirstOrDefault`, **`Pets.Any`** on live lists, **`foreach` on live `PlayerCombatState.Pets`**, or raw zone `FirstOrDefault` when multiple instances could match or the loop can mutate the list:
  - `PetsOrderedByCombatId` / `FirstPetWhere` — pet lookup by predicate (e.g. source field card binding).
  - Internally, these helpers are snapshot-first (`PetsSnapshotOrderedByCombatId`) so lookup/scan APIs do not enumerate live `PlayerCombatState.Pets`.
  - `PetsAny` — **`Any`-style** checks over **`PetsSnapshotOrderedByCombatId`** (stable predicate scan order + no live-list iteration).
  - `PetsSnapshotOrderedByCombatId` — **`foreach`** over an ordered copy (avoids `InvalidOperationException` + fixes cross-peer iteration order).
  - `PetsSnapshotAliveDuelMonstersOrderedByCombatId` — alive **duel** field pets from that snapshot (no live `Pets.Where`); use for mass kill / damage loops that must not enumerate `Pets` during mutation.
  - `PlayersSnapshotOrderedByNetId` — stable fan-out over `cs.Players` / `runState.Players` when owner/zone/power reconcile passes walk all players; avoids hidden list-order drift between peers.
  - `CreatureListOrderedByCombatId` — tribute / grid **`IEnumerable<Creature>`** material lists before kills.
  - `FindPetByCombatId` — menu / net payloads keyed by `CombatId` (uses **`FirstPetWhere`**; unique `CombatId` match).
  - `CardsOrderedForMp` / `FirstCardWhereStable` / `FirstCardWithNetId` — spell/trap zone (and similar) “pick one” when ties are possible: order by **`NetCombatCardDb` id** then **`CardId.Entry`**.
- Order by **`CombatId`** before `FirstOrDefault` / “first matching pet” when the contract is “the pet bound to this field card,” not “whichever the list happens to return first.”
- `MonsterActivatedEffectRuntime.FindPetForSourceMonster` and `BaseMonsterCard` `GetSourcePet*` paths should stay aligned with that rule.

**Narrow Pass / field tax:**

- `YgoNarrowPassField.GetFirstActive` must not depend on raw pile order when multiple `IYgoMonsterCommandFieldTaxContributor` could be active — **stable sort** before choosing.

**Checksum reconciliation:**

- `NetFullCombatStateYgoChecksumPatch`, `YgoMonsterCommandChecksumReconcile`, `MonsterCommandRegistry.ApplyDieForYouSyncForChecksum`, `DuelMonsterStancePowerSync.ApplyStanceFromSourceCardSyncForChecksum`, `SevenWeaponsHunterState.ApplySyncForChecksumIfHunter` — when async `PowerCmd` cannot finish before snapshot, **sync internal** state must match what gameplay would have produced.

**Potions / grids that use RNG on a filtered pool:**

- Pool order before shuffle must be **stable in MP** (e.g. sort by `CardId.Entry`) if the same RNG draw must yield the same options on both peers.
- Preview-only result grids that still consume a player-choice id should use **`YgoPreviewGridSelection.ShowPreviewAsync(...)`** (backed by synced indexed wire) instead of vanilla `CardSelectCmd.FromSimpleGrid(...)`.
- Optional activate / choose-one grids over combat card lists from piles should use **`TributeSummonGridSelect.FromSimpleGridCombat(...)`** with **`YgoMpCombatOrder.CardsSnapshotOrderedForMp(...)`**-backed candidate collection / rebuild callbacks, even when the UI is not literally a tribute or ritual flow.

**Pet death:**

- `DuelMonsterPetDeathPatch` defers relocation to avoid deadlocks; anything that **changes serialized combat state** in that tail must be understood relative to **when** checksum runs for the enclosing action.

1. Both peers: `SlayTheSpire2/logs/godot.log` (and client copy, e.g. `Laptop/godot.log`).
2. Search **`[ERROR] State divergence`** and **`ERROR:`** (filter Godot exit RID noise if unrelated).

| **Ritual from second-hand row (checksum 87)** | `PlayCardFromOptionPilePatch` on `PlayCardAction.ExecuteAction` at **priority 0** returned **`false`** before **`PlayCardActionRitualSpellPatch` (850)**, so rituals on **`YgoCardOptionPile`** never ran **`TrySelectRitualResolutionAsync` / `RitualSpellPlayPayload.SetPending`**. Other peers on hand/STZ path could still run the full ritual → **real desync** after the same `PlayCardAction`. |
| **Fusion target branching** | When `needTargetGrid` was false on the observer (only **one** legal fusion in extra deck) but **true** on the host (two+), the observer **skipped** the fusion-target `ReserveChoiceId` step. Later grids (materials, merchant, etc.) **shifted IDs** and consumed wrong buffered results (checksum 73 / merchant `AsDeckCards` crash). |
| **Extra deck enumeration** | Unstable iteration order for feasible fusion targets made `needTargetGrid` disagree across peers before any grid ran. |
| **Variable tribute (field-only)** | `FromSimpleGridIndexed` (Index-only wire) vs `FromSimpleGridCombat` (`NetCombatCard` + `GridCombatMpExpectation`): field-only grids (e.g. BEWD + Totem) could diverge; Mausoleum synthetic rows still need the indexed path. |
| **Stale grid buffers** | `GridCombatMpExpectation` validated index **count** vs min/max but not **row count**: a pre-buffered `indexes=[1]` from an **earlier** multi-row grid satisfied a **one-row** tribute wait, then checksum exploded (checksum 86). |
| **Spell/trap + PrePlay grid** | Observers: `card.Pile` null/stale after deserialize; PrePlay prefix returned early → **vanilla** `PlayCardAction` finished in one tick with **no** `[MP][PrePlayGrid] begin` while host ran full trap flow (checksum 51 / Raigeki Break). **Also:** `PlayCardFromSpellTrapZonePatch` at **HarmonyPriority 900** ran **before** `PlayCardActionPrePlayCancelableGridPatch` (790) and could **short-circuit** observers so `OnPlay` never mirrored for `IYgoPrePlayCancelableGridSelection`. |
| **Rest site PreHeal** | `CombatStateSynchronizer` **inside** `ExecuteRestSiteHeal` blocked the client in `WaitForSync` while the host continued (“0 FPS” / frozen rest); host later saw peer disconnect. |
| **Remote mirror resources** | Incorrect **skip** of `SpendResources` on observers for defense/set paths caused energy/star drift; a later incorrect **always-skip** hypothesis was refuted by dumps (host 2/0 vs client 3/1). Lesson: mirror must match **authoritative** spend; prove with dumps, not assumptions. |
| **Potions / `GetDistinctForCombat`** | Same combat RNG + `UnstableShuffle`, but **different input sequence** from `GetUnlockedCards` / `Distinct` → different top-3 skill options → same UI index mapped to **different cards** (checksum after Skill Potion). |
| **Pet death + main thread** | `DuelMonsterPetDeathPatch` used `GetResult()` on the thread still inside `CreatureCmd.Kill` / `OnPetDied`; `GuardianSpiritPower` awaited `GainBlock` → `Cmd.Wait` / timers → **deadlock** (union XYZ option pile never reached END). |
| **Callable + Task** | `Callable.From(() => TaskHelper.RunSafely(...))` **returned** a `Task`; Godot marshals return value to `Variant` → logged error. Fix: void lambda ` _ = TaskHelper.RunSafely(...)`. |
| **Union / banish materials** | `Kill` → GY → `BanishCard` pulled extra death/timer behavior; `ReleaseLiveFieldMonsterToBanishedAsync` initially did not remove duel pets from combat because guards used `PlayerCreatures`/`Enemies` only (duel pets: ally, `Player == null`) → `CountLiveDuelMonsters` still saw materials → `TrySummonDuelMonsterSpecial` false. |

| **Needle Ball / Die For You** | Self-hit used `ValueProp.Move` **without** `Unpowered` → treated as powered → `DieForYouPower` + `Hook.ModifyUnblockedDamageTarget` order diverged (checksum 127). |
| **Narrow Pass “first active”** | `GetFirstActive` depended on raw pile order when multiple tax cards could qualify. |

### Fixes and positive patterns (from sessions)

| Area | What worked |
|------|-------------|
| **Fusion / ritual / tribute grids** | Route target + material selection through `TributeSummonGridSelect.FromSimpleGridCombat` with `StabilizeHandPileCandidates` and `rebuildCanonicalForRemoteApply` (same contract as rituals). In MP with **exactly one** feasible fusion, still run the **degenerate** synced target grid so every peer consumes the same remote step. Sort fusion targets from extra deck in **`NetCombatCardDb` id order** before branching. **Combat-card wire** specifically closes cases where the same grid index would otherwise point at different cards when an equip (or similar) is in **hand on one peer** and **spell/trap zone** on the other (Graceful Charity / **checksum 53** postmortem). |
| **Trunk marker serialization** | Align **`YgoSaveTrunkSideMarkerCard.MaxUpgradeLevel`** (or equivalent) with the **max value actually written** into `CurrentUpgradeLevel` by `PlayerToSerializableAppendYgoTrunkSidePatch` so `FromSerializable` never rejects host deck payloads on join/sync. |
| **Ritual + fusion vs option-pile prefix order** | Run **`PlayCardActionRitualSpellPatch`** and **`PlayCardActionFusionSpellPatch`** at **`[HarmonyPriority(-1000)]`** so they execute **before** `PlayCardFromOptionPilePatch`. Treat **`YgoCardOptionPile`** like hand/STZ for ritual/fusion entry; after `OnPlayWrapper`, call **`PlayCardFromOptionPilePatch.SchedulePostPlayCleanup`** when the source row was the option pile. Extend **`YgoPlayCardQueueDeferral`** so deferred enqueue rules apply to **`YgoCardOptionPile`** the same as hand/STZ. Optional **`[YgoDuelist][MP][Ritual|Fusion] Prefix: intercept … from option pile`** lines to prove both peers took the prefix. |
| **Patch usings (Godot vs game `Player`)** | In Harmony patches that reference **`MegaCrit.Sts2.Core.Entities.Players.Player`**, avoid **`using Godot`** at file scope (it can bind `Player` to **`Godot.Player`**). Prefer **`Godot.GD.Print`** qualification instead of bare `GD`. |
| **Indexed vs combat wire** | Field-only tribute: `FromSimpleGridCombat` when **no** `Mausoleum_Lose_HP` rows; keep `FromSimpleGridIndexed` when Mausoleum rows exist. Log `[YgoDuelist][MP][Tribute] ... combatWire=...`. |
| **Stale Index buffer** | `GridCombatMpExpectation.CandidateRowCount`; set from `cards.Count` in `FromSimpleGridCombat` / equip grids; `PlayerChoiceSynchronizerStaleReceivePatch` drops out-of-range pre-buffered Index results before `WaitForRemoteChoice`. |
| **Preview/grid choice-id drift** | Custom grid helpers must install `GridCombatMpExpectation` **before** `ReserveChoiceId`; otherwise the reserve postfix cannot bind `ExpectedChoiceId`, and a later valid empty-index preview result (e.g. Graceful Dice id 5 while observer waits on id 2) can be buffered instead of remapped to the active wait. The wait-prefix fallback binds missing ids, but the correct pattern is expectation scope -> reserve id -> local sync / remote wait -> dispose scope. |
| **PrePlay + STZ** | `TryResolveAllowedPrePlayPlaySource`: infer pile via `Cards.Contains(card)` on hand / STZ / option piles in MP when `card.Pile` is wrong. `PlayCardFromSpellTrapZonePatch`: **defer** `IYgoPrePlayCancelableGridSelection` to PrePlay patch (`return true` early) so priority 900 does not eat the flow. |
| **Diagnostics** | `YgoMpDiagnostics.VerbosePrint`, `PREFIX_SKIP_DESYNC_RISK` / `execute_abort_no_pile` when PrePlay cannot resolve pile on one peer only. |
| **Rest site** | Remove **PreHeal** `StartSync`/`WaitForSync` from heal option; keep **PostHeal** round-trip via `TaskHelper.RunSafely` after the option completes. |
| **Remote mirror** | `PlayCardActionRemoteHandDuelMonsterFixPatch`: align `SpendResources` with host-authoritative behavior; use **explicit logs** (`spentEnergy`, before/after) to prove parity. |
| **Potions** | `CardFactoryGetDistinctForCombatMpStableOrderPatch`: in MP combat, stable-sort pool by `CardId.Entry` before `UnstableShuffle` + `Take`. |
| **Pet death** | Deferred tail: `Callable.From(() => { _ = TaskHelper.RunSafely(tailAsync()); }).CallDeferred()` (void body). `ContainsCreature` + unregister/kill so **Pets** updates for duel allies. |
| **Banish materials** | `ReleaseLiveFieldMonsterToBanishedAsync` / fusion `BanishesFusionMaterials`: move field monster card straight to banished; equips to GY; avoid Kill+Banish round-trip where inappropriate. |
| **Pets everywhere** | `PetsSnapshotOrderedByCombatId` before turn-reset iteration; **`YgoMpCombatOrder.FirstPetWhere`** (or equivalent) for field-bound pet resolution — Reckless, `FindPetForSourceMonster`, `GetSourcePet*`, attack/defend/battle-position command lookup, stance sync. |
| **Prompted flip effects** | Reveal face-down prompt candidates immediately, then use the synced grid only to choose effect activation. Aggregate same-frame candidates before opening the prompt; use `MinSelect=1` + manual confirm + cancelable so confirm cannot submit zero cards, but cancel still intentionally skips. Do not keep the `FaceDown=false` / pet stance-power mutation behind the async prompt result; it can complete before/after turn-start checksum on different peers. |
| **Checksum-only power markers** | Cosmetic marker reconciles before `NetFullCombatState.FromRun` should not call `PowerCmd`, and should avoid `PowerModel.ApplyInternal` when a guarded internal mutable-list path is available; those can create UI/power nodes and load textures during checksum. Do not treat public `Creature.Powers` or `PowerModel.Owner` as mutable. Remove all stale copies before applying an authoritative singleton marker; `GetPower<T>()` only finds one copy. |
| **Card-owned pet power stacks** | If a field monster stores authoritative stacks on the source card but mirrors them as a pet power, reconcile the pet power before checksum from the card value (Big Shield Gardna `FortifiedBeastStacks` -> `FortifiedBeastPower`). Registry state for forced powers must also be restored even when the visible power already exists. |
| **Duel pet visual roster** | After pet death, banish-release, or hand-release, remove the `NCreature` node if still present and rerun ally pet layout + draw ordering. Summon/add patches are not enough because vanilla does not reshuffle surviving pets when a duel monster leaves. |
| **Life costs** | Needle Ball-style self damage: `Move \| Unpowered` so Die For You does not redirect. |
| **Narrow Pass / Seven Weapons** | Stable sort for first active; `SyncHunterPetsAsync` snapshots pets. |
| **UI guards** | `NCardPlayQueueSkipDisposedTweenCancellationPatch`; `NHealthBarDisposedChildrenGuardPatch`. |
| **Localization** | Copycat-style arrows: avoid raw `>` inside nested BBCode; use a Unicode arrow in `cards.json`. |
| **Model registration** | Avoid `RelatedCards` that re-register the same type twice (e.g. Gravekeeper’s Guard). |

### Process lessons (these threads)

- **Evidence first:** diff `LOCAL STATE DUMP` and `[YgoDuelist][MP][Checksum][fp]` on both machines; same `fp` + different hash vs different `fp` narrows pile vs field-not-in-fp.
- **Do not treat every `ERROR:` as netcode:** shutdown RID leaks and draft cancel noise are normal; separate **Neow/UI parse** failures from combat divergence.
- **Stale logs:** combined `godot.log` files may contain **multiple runs**; rename or truncate before a repro so the first `[ERROR]` maps to one session.
- **Deploy:** `SlayTheSpire2.exe` locking `YgoDuelist.dll` causes copy failures; close the game or copy the built DLL manually from `.godot/mono/temp/bin/Release/`.
- **Mechanical prevention beats file-by-file audit:** repo-wide greps for the footguns in the table above, then route new code through shared helpers (already aligned with “Mechanical repo pass” and “Ground rules” in this doc).
- **Client log missing:** if `Laptop/godot.log` is absent from the workspace, still triage from the host log **and** confirm whether the failure is a **thrown exception** during sync vs a **checksum mismatch** after gameplay (different fixes).
- **Broaden first-pass log grep:** add `InvalidOperationException`, `Exception`, `desync`, `Steam`, `WaitForSync` to `[ERROR]` scans so **deck apply** crashes are not missed when the user only said “ERROR”.
- **Harmony order is control flow:** the first prefix that returns **`false`** on `ExecuteAction` **wins**; “my patch runs later at higher priority” is false for prefixes — later **postfixes** run in reverse order, but **prefix** short-circuit is what bit ritual-from-option-row.
- **Post-fix verification grep:** after MP ritual/fusion changes, search both logs for **`[YgoDuelist][MP]`** plus **`State divergence`** on the same repro card.
- **Choice expectation invariant:** every `ReserveChoiceId` / `WaitForRemoteChoice` pair must be audited as a transaction. The expectation contract is incomplete until `ExpectedChoiceId` is bound; grep for `expectedChoiceId=?` in logs after any selector change, because that means the sanity filter can validate shape but cannot prove prompt ownership.
